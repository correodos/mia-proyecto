# ESPECIFICACIONES DEFINITIVAS — DISEÑO VISUAL Y UX

## 1. Objetivo del diseño

El objetivo es transformar la web actual, que ya es funcional, en una web de calculadoras de horas profesional, clara, moderna y fácil de utilizar.

El diseño debe priorizar la utilidad y la facilidad de uso por encima de los elementos decorativos.

### 1.1 Objetivo principal

Conseguir que cualquier usuario pueda utilizar las calculadoras de forma rápida y sencilla, entendiendo inmediatamente:

- qué puede calcular;
- qué datos debe introducir;
- dónde introducirlos;
- qué acción debe realizar;
- cuál es el resultado obtenido.

### 1.2 Apariencia profesional

La web debe tener una identidad visual propia y dejar de presentar el contenido como una página de texto o documentación.

Se trabajará especialmente la:

- jerarquía visual;
- distribución del contenido;
- tipografía;
- utilización del espacio;
- navegación;
- formularios;
- botones;
- resultados;
- tarjetas;
- adaptación a dispositivos móviles.

### 1.3 Coherencia visual

Todas las páginas deben formar parte de un mismo sistema visual.

Las calculadoras, guías, página principal y futuras herramientas deben compartir los mismos criterios de diseño.

### 1.4 Simplicidad y claridad

El diseño debe ser limpio y funcional.

No se añadirán elementos decorativos que dificulten la lectura, la navegación o el uso de las calculadoras.

### 1.5 Prioridad móvil

El diseño debe proporcionar una experiencia especialmente cómoda en dispositivos móviles, manteniendo al mismo tiempo una correcta presentación en tabletas y ordenadores.

### 1.6 Escalabilidad

El sistema visual debe permitir incorporar nuevas calculadoras y páginas sin necesidad de crear un diseño independiente para cada una.

### 1.7 Conservación de la funcionalidad

El rediseño visual no debe alterar la lógica ni el funcionamiento existente.

Se deben conservar:

- cálculos;
- validaciones;
- tests;
- URLs;
- estructura SEO;
- navegación;
- funcionalidades existentes.

Cualquier modificación funcional deberá justificarse de forma independiente.

## 2. Principios generales de diseño

El diseño de toda la web debe seguir un conjunto de principios comunes para garantizar claridad, facilidad de uso, coherencia y escalabilidad.

### 2.1 Claridad por encima de la decoración

La información debe entenderse rápidamente.

Los elementos visuales deben ayudar al usuario a comprender la página y utilizar la herramienta, no distraerlo.

### 2.2 Diseño limpio y moderno

La web debe tener una apariencia actual, profesional y sencilla.

Se evitará el exceso de:

- colores;
- sombras;
- animaciones;
- elementos decorativos;
- efectos visuales innecesarios.

### 2.3 Prioridad a las calculadoras

Las calculadoras son el elemento principal del proyecto.

El diseño debe facilitar que el usuario:

1. identifique la herramienta;
2. introduzca los datos;
3. ejecute el cálculo;
4. interprete el resultado.

El resultado debe tener suficiente protagonismo visual.

### 2.4 Jerarquía visual clara

Debe existir una diferencia visual clara entre:

- títulos;
- subtítulos;
- texto introductorio;
- secciones;
- campos de formulario;
- botones;
- resultados;
- información secundaria.

### 2.5 Lectura cómoda

El contenido textual debe utilizar un ancho adecuado, tamaños de letra legibles y suficiente separación entre elementos y bloques de contenido.

### 2.6 Consistencia visual

Los elementos equivalentes deben utilizar siempre los mismos criterios visuales.

Por ejemplo:

- botones;
- campos de formulario;
- tarjetas;
- enlaces;
- títulos;
- mensajes de error;
- bloques de resultados.

### 2.7 Interacción evidente

El usuario debe poder identificar fácilmente qué elementos son interactivos.

Los botones y enlaces deben diferenciarse claramente del contenido informativo.

### 2.8 Feedback de la interfaz

Toda acción relevante debe proporcionar una respuesta visual clara.

Se contemplarán como mínimo:

- estado normal;
- interacción;
- focus;
- error;
- resultado;
- reinicio.

### 2.9 Diseño responsive

El diseño debe funcionar correctamente desde el principio en:

- móviles;
- tabletas;
- ordenadores.

La versión móvil no debe considerarse una adaptación secundaria.

### 2.10 Accesibilidad

La accesibilidad forma parte del diseño.

Se prestará atención especialmente a:

- contraste;
- legibilidad;
- labels;
- navegación mediante teclado;
- estados de focus;
- tamaño de elementos interactivos;
- estructura semántica.

### 2.11 Rendimiento

El diseño debe mantenerse técnicamente sencillo.

No se añadirán librerías, recursos, animaciones o efectos que no aporten un beneficio claro al usuario.

### 2.12 Escalabilidad

El sistema visual debe poder reutilizarse en nuevas calculadoras, guías y páginas sin crear diseños independientes para cada página.

## 3. Identidad visual

La identidad visual debe transmitir que la web es una herramienta práctica, sencilla y fiable para realizar cálculos relacionados con horas, horarios y tiempo de trabajo.

La estética debe ser profesional y moderna, pero sin resultar excesivamente corporativa, recargada o compleja.

### 3.1 Paleta de colores

Se utilizará una paleta reducida y coherente.

#### Color principal

Se utilizará un tono azul como color principal de la identidad visual.

Su función será destacar:

- botones principales;
- enlaces importantes;
- elementos interactivos;
- elementos destacados de la interfaz.

#### Fondos

Se utilizarán principalmente:

- blanco;
- gris muy claro.

Los fondos deben proporcionar suficiente contraste y mantener una apariencia limpia.

#### Texto

El texto principal utilizará un tono oscuro, evitando preferentemente el negro absoluto.

El texto secundario podrá utilizar tonos grises para establecer jerarquía visual.

#### Estados

Se utilizarán colores específicos y consistentes para los diferentes estados:

- verde para resultados o estados positivos;
- rojo para errores;
- amarillo o ámbar para avisos.

Estos colores no sustituirán al texto y no serán el único medio para comunicar información.

### 3.2 Tipografía

Se utilizará una tipografía sans-serif moderna y de alta legibilidad.

Se priorizará el uso de fuentes del sistema siempre que sea posible para evitar dependencias externas innecesarias y mantener un buen rendimiento.

La jerarquía tipográfica deberá diferenciar claramente:

- H1;
- H2;
- H3;
- texto principal;
- texto secundario;
- etiquetas;
- resultados;
- mensajes de error.

### 3.3 Estilo general

La identidad visual seguirá estos principios:

- minimalista;
- profesional;
- clara;
- accesible;
- amigable;
- funcional.

La web no debe parecer un blog, una aplicación empresarial compleja ni una plantilla genérica.

Debe transmitir principalmente la idea de una herramienta sencilla que permite resolver rápidamente una necesidad concreta.

### 3.4 Bordes, radios y tarjetas

Los componentes podrán utilizar:

- bordes suaves;
- esquinas ligeramente redondeadas;
- sombras discretas cuando aporten separación visual;
- suficiente espacio interior.

Se evitará el uso excesivo de sombras, bordes decorativos o efectos visuales.

### 3.5 Botones

Los botones deberán establecer una jerarquía clara entre acciones.

La acción principal de una calculadora, normalmente `Calcular`, tendrá mayor protagonismo visual.

Las acciones secundarias, como `Reiniciar`, tendrán un tratamiento visual menos destacado.

Los botones deberán ser suficientemente grandes para resultar cómodos en dispositivos táctiles.

### 3.6 Resultados

El resultado de una calculadora será uno de los elementos visualmente más destacados de la página.

Debe poder localizarse rápidamente y diferenciarse claramente de:

- los datos introducidos;
- las instrucciones;
- el contenido informativo.

La presentación del resultado deberá mantener la coherencia visual entre todas las calculadoras.

Se podrán utilizar elementos desplegables para reducir la carga visual de páginas con contenido extenso.

Los desplegables podrán utilizarse especialmente para:

- ejemplos;
- pasos detallados;
- explicaciones complementarias;
- fórmulas;
- casos especiales;
- preguntas frecuentes;
- información avanzada.

La información imprescindible para utilizar una calculadora o comprender el objetivo principal de una página deberá permanecer visible.

Los elementos desplegables deberán:

- indicar claramente que pueden abrirse;
- tener un área de interacción cómoda;
- funcionar correctamente en dispositivos móviles;
- ser accesibles mediante teclado;
- mantener estados visuales claros de abierto y cerrado.

No se utilizarán desplegables de forma indiscriminada. Su finalidad será mejorar la legibilidad y reducir la carga visual, no ocultar contenido importante.

## 4. Estructura global de la web

Todas las páginas deben compartir una estructura global coherente que facilite la navegación y permita reconocer rápidamente que forman parte del mismo sitio.

La estructura general será:

**Header → contenido principal → footer**

Se evitarán elementos globales innecesarios que puedan distraer del contenido principal.

### 4.1 Header

El header debe identificar claramente la web y proporcionar acceso a la navegación principal.

Debe:

- mostrar claramente el nombre o identidad de la web;
- contener la navegación principal;
- ocupar una altura moderada;
- mantener una apariencia limpia;
- adaptarse correctamente a dispositivos móviles.

En dispositivos móviles se utilizará una navegación adaptada al espacio disponible.

### 4.2 Navegación

La navegación debe facilitar el acceso a las principales calculadoras y contenidos del sitio.

Las herramientas podrán organizarse por categorías, especialmente:

- Calculadoras;
- Guías.

La navegación no deberá contener un número excesivo de enlaces ni elementos innecesarios.

Las calculadoras y contenidos principales deben poder localizarse rápidamente.

### 4.3 Contenedor principal

El contenido principal tendrá un ancho máximo adecuado para mantener una lectura cómoda en pantallas grandes.

El contenido no deberá ocupar todo el ancho disponible en ordenadores.

En dispositivos móviles se utilizará prácticamente todo el ancho disponible, manteniendo márgenes laterales suficientes para facilitar la lectura y la interacción.

### 4.4 Footer

El footer será sencillo y funcional.

Podrá contener:

- identidad de la web;
- enlaces principales;
- navegación secundaria;
- enlaces legales cuando sean necesarios;
- información de copyright cuando corresponda.

No se utilizará el footer para introducir grandes cantidades de enlaces con fines exclusivamente SEO.

### 4.5 Navegación contextual

Las páginas podrán incluir elementos de navegación contextual para indicar al usuario dónde se encuentra dentro del sitio.

Se podrán utilizar:

- enlaces para volver a la página principal;
- enlaces a la categoría correspondiente;
- enlaces a herramientas relacionadas;
- enlaces a contenidos relacionados.

La navegación contextual deberá ayudar al usuario sin generar una interfaz excesivamente cargada.

## 5. Página de inicio

La página de inicio debe funcionar como el punto principal de entrada al sitio y permitir al usuario comprender rápidamente qué ofrece la web y acceder a las calculadoras.

La portada debe tener una jerarquía visual clara y evitar la apariencia de una página formada únicamente por títulos, párrafos y enlaces de texto.

### 5.1 Hero

La parte superior de la página debe comunicar de forma inmediata:

- qué ofrece la web;
- para qué sirve;
- qué puede hacer el usuario.

El H1 debe tener protagonismo visual.

El hero podrá incluir:

- título principal;
- breve descripción;
- llamada a la acción principal.

No se utilizarán imágenes o elementos decorativos de gran tamaño si no aportan una utilidad clara.

### 5.2 Presentación

Se podrá incluir una breve introducción que explique el propósito del sitio.

La introducción deberá ser concisa y evitar grandes bloques de texto.

El contenido informativo extenso se reservará principalmente para las páginas de guías.

### 5.3 Sección de calculadoras

Las calculadoras serán el elemento principal de la página de inicio.

Cada herramienta se presentará mediante un componente visual diferenciado, preferentemente una tarjeta.

Cada tarjeta deberá incluir como mínimo:

- nombre de la calculadora;
- descripción breve.

La tarjeta completa funcionará como enlace hacia la calculadora correspondiente. No será necesario incluir un botón independiente dentro de la tarjeta.

Podrá incluir también un icono cuando este aporte valor visual o facilite la identificación de la herramienta.

Las tarjetas deberán mantener una estructura visual uniforme.

Actualmente se deben presentar las siguientes calculadoras:

- Calculadora de horas trabajadas;
- Calculadora semanal de horas;
- Calculadora de horas extra;
- Calculadora de jornada partida;
- Calculadora entre fechas.

El sistema deberá permitir añadir nuevas calculadoras posteriormente sin modificar el diseño general.

### 5.4 Sección de guías

Las guías se presentarán en una sección diferenciada de las calculadoras.

El diseño deberá permitir distinguir claramente entre:

- herramientas para calcular;
- contenidos para aprender.

Actualmente se deben presentar:

- Cómo calcular horas trabajadas;
- Calcular horas trabajadas con descanso.

Cada guía deberá incluir:

- título;
- descripción breve;
- enlace para acceder al contenido.

### 5.5 Llamadas a la acción

Las llamadas a la acción deben utilizar textos claros y descriptivos.

Ejemplos:

- Calcular ahora;
- Usar calculadora;
- Ver calculadoras;
- Leer guía.

La página no deberá utilizar llamadas a la acción excesivas o repetitivas.

### 5.6 Orden visual

La estructura visual recomendada será:

1. Hero;
2. Calculadoras;
3. Guías;
4. Información complementaria cuando sea necesaria;
5. Footer.

Las calculadoras tendrán prioridad visual sobre el contenido secundario.

### 5.7 Contenido y carga visual

La página de inicio no debe convertirse en un artículo extenso.

Su función principal será:

- presentar el sitio;
- facilitar el acceso a las herramientas;
- orientar al usuario hacia contenidos relacionados.

Los textos extensos y explicaciones detalladas deberán mantenerse en sus páginas correspondientes.

### 5.8 Escalabilidad

El diseño de la página de inicio deberá permitir incorporar nuevas calculadoras y contenidos sin romper la estructura visual existente.

Las nuevas herramientas deberán poder añadirse reutilizando los componentes establecidos.

## 6. Páginas de calculadoras

Las páginas de calculadoras deben estar diseñadas para que el usuario pueda realizar el cálculo de forma rápida, clara y sencilla.

La calculadora será el elemento principal de la página y deberá tener mayor protagonismo visual que el contenido complementario.

### 6.1 Título

Cada calculadora tendrá un H1 claro y descriptivo que indique exactamente qué permite calcular.

### 6.2 Introducción

Debajo del título se podrá incluir una breve explicación sobre la utilidad de la calculadora.

El texto deberá ser conciso y explicar al usuario qué puede calcular y qué datos necesita introducir.

### 6.3 Formulario

El formulario de la calculadora deberá ocupar una posición central y claramente diferenciada del resto del contenido.

Los campos deberán presentarse siguiendo un orden lógico que facilite su utilización.

No se añadirán campos o pasos que no sean necesarios para realizar el cálculo.

### 6.4 Campos

Cada campo deberá tener una etiqueta clara y permitir identificar fácilmente qué dato debe introducir el usuario.

Los campos deberán mantener una estructura visual uniforme en todas las calculadoras.

Se conservarán los campos y funcionalidades existentes salvo que exista una razón concreta para modificarlos.

### 6.5 Botones

Cada calculadora deberá disponer de una acción principal claramente identificable para realizar el cálculo.

Las acciones secundarias, como reiniciar el formulario, tendrán menor protagonismo visual.

### 6.6 Resultados

El resultado deberá aparecer en una zona claramente diferenciada del formulario.

Deberá tener suficiente protagonismo visual para que el usuario pueda identificarlo rápidamente.

La información mostrada deberá ser clara y fácil de interpretar.

### 6.7 Errores y validaciones

Los mensajes de error y validación deberán mostrarse de forma clara y próxima al elemento correspondiente cuando sea necesario.

Los errores deberán explicar qué debe corregir el usuario.

No se utilizarán mensajes ambiguos o exclusivamente visuales.

### 6.8 Información complementaria

La información adicional sobre el funcionamiento de la calculadora se mantendrá separada del formulario principal.

Podrá incluir:

- explicación del cálculo;
- ejemplos;
- fórmulas;
- casos especiales;
- preguntas frecuentes.

La información complementaria podrá utilizar elementos desplegables cuando permita reducir la carga visual sin ocultar información esencial para utilizar la calculadora.

La calculadora deberá seguir siendo comprensible y utilizable sin necesidad de consultar estos contenidos adicionales.

## 7. Páginas de contenido / guías

Las páginas de contenido estarán destinadas principalmente a explicar conceptos, procedimientos y formas de realizar cálculos relacionados con horas, horarios y tiempo de trabajo.

El diseño deberá facilitar la lectura y diferenciar claramente estas páginas de las calculadoras.

### 7.1 Jerarquía de títulos

Las guías deberán utilizar una estructura clara de títulos y subtítulos.

El H1 identificará el tema principal de la guía.

Los H2 y H3 se utilizarán para organizar correctamente las diferentes secciones.

### 7.2 Texto

El contenido deberá presentarse en bloques de texto fáciles de leer.

Se evitarán párrafos excesivamente largos y grandes bloques de texto sin separación visual.

La información deberá estar organizada de forma progresiva, comenzando por los conceptos más importantes.

### 7.3 Ejemplos

Cuando una explicación pueda beneficiarse de un ejemplo práctico, se podrá incluir un ejemplo relacionado con situaciones reales de cálculo de horas.

Los ejemplos deberán ser claros y estar visualmente diferenciados del texto general.

### 7.4 Bloques destacados

Se podrán utilizar bloques visuales para destacar información especialmente relevante, como:

- fórmulas;
- resultados de ejemplos;
- consejos;
- advertencias;
- conceptos importantes.

Estos elementos deberán utilizarse de forma moderada y mantener la coherencia visual con el resto del sitio.

### 7.5 Navegación relacionada

Las guías podrán incluir enlaces hacia calculadoras y otros contenidos relacionados cuando sean útiles para el usuario.

Los enlaces deberán integrarse de forma natural dentro del contenido y facilitar la continuación de la navegación.

La navegación relacionada no deberá utilizarse para añadir enlaces innecesarios.

## 8. Componentes reutilizables

La web deberá utilizar componentes y estilos reutilizables para mantener una apariencia coherente y facilitar la incorporación de nuevas páginas y calculadoras.

Los componentes equivalentes deberán utilizar una estructura y un comportamiento visual común en todo el sitio.

### 8.1 Tarjetas

Las tarjetas se utilizarán para presentar elementos agrupados, como:

- calculadoras;
- guías;
- contenidos relacionados.

Deberán mantener una estructura visual coherente y poder reutilizarse en diferentes páginas.

### 8.2 Botones

Los botones deberán utilizar estilos comunes en toda la web.

Se establecerá una jerarquía visual entre:

- acciones principales;
- acciones secundarias.

No se crearán estilos independientes para cada calculadora cuando la acción sea equivalente.

### 8.3 Formularios

Los campos de formulario deberán compartir criterios visuales comunes.

Se mantendrá una estructura coherente para:

- etiquetas;
- campos;
- ayudas;
- mensajes asociados.

### 8.4 Alertas

Los mensajes de información, aviso, error o confirmación deberán utilizar componentes visuales coherentes.

Su diseño deberá permitir identificar fácilmente el tipo de mensaje.

### 8.5 Resultados

Los resultados de las calculadoras deberán utilizar un sistema visual común.

Aunque cada calculadora pueda mostrar información diferente, la presentación deberá mantener una jerarquía y estructura reconocibles.

### 8.6 Enlaces

Los enlaces deberán mantener un estilo coherente en todo el sitio y diferenciarse claramente del texto normal.

Los enlaces que representen acciones o navegación deberán utilizar textos descriptivos.

### 8.7 Contenido desplegable

Los elementos desplegables podrán utilizarse para mostrar información complementaria sin sobrecargar visualmente las páginas.

Deberán mantener un comportamiento y una apariencia comunes en todas las páginas donde se utilicen.

Se utilizarán principalmente para contenido secundario, como:

- ejemplos;
- explicaciones detalladas;
- fórmulas;
- preguntas frecuentes;
- casos especiales.

## 9. Diseño responsive

La web deberá adaptarse correctamente a diferentes tamaños de pantalla, manteniendo la funcionalidad, la legibilidad y una experiencia de uso cómoda.

El diseño responsive deberá formar parte de la implementación desde el principio y no tratarse como una adaptación posterior.

### 9.1 Escritorio

En pantallas grandes:

- el contenido utilizará un ancho máximo adecuado;
- las calculadoras y guías podrán organizarse mediante rejillas cuando resulte apropiado;
- las tarjetas mantendrán una distribución equilibrada;
- los formularios tendrán un ancho cómodo para introducir datos;
- los resultados dispondrán de espacio suficiente para mostrarse claramente;
- la navegación principal permanecerá visible y ordenada.

### 9.2 Tablet

En tamaños intermedios:

- las rejillas deberán adaptarse automáticamente al espacio disponible;
- las tarjetas podrán reducir el número de columnas;
- los formularios deberán mantener una correcta distribución de los campos;
- los márgenes y espacios se ajustarán para evitar una apariencia excesivamente comprimida;
- no se deberá perder ninguna funcionalidad disponible en escritorio.

### 9.3 Móvil

En dispositivos móviles:

- los contenidos se organizarán principalmente en una sola columna cuando sea necesario;
- las tarjetas ocuparán el ancho disponible respetando márgenes laterales adecuados;
- los campos de formulario deberán resultar cómodos para introducir datos;
- los botones deberán disponer de espacio suficiente para ser utilizados mediante pantalla táctil;
- no deberá existir desplazamiento horizontal innecesario;
- la navegación deberá adaptarse al espacio reducido;
- los resultados deberán mantener una jerarquía visual clara;
- ningún contenido o funcionalidad importante deberá desaparecer únicamente por utilizar una pantalla pequeña.

La adaptación móvil deberá conservar la misma identidad visual y estructura conceptual que la versión de escritorio.

## 10. Accesibilidad

La accesibilidad deberá formar parte del diseño de todas las páginas y calculadoras.

El objetivo es que las herramientas puedan utilizarse de forma clara y cómoda por el mayor número posible de usuarios.

### 10.1 Contraste

Los textos y elementos interactivos deberán mantener un contraste suficiente con respecto a su fondo.

Los colores utilizados para indicar estados no deberán ser el único medio para comunicar información.

### 10.2 Focus

Los elementos interactivos deberán mostrar un estado de focus claramente visible cuando se navegue mediante teclado.

El focus no deberá eliminarse mediante CSS sin proporcionar una alternativa visible.

### 10.3 Labels

Todos los campos de formulario deberán disponer de etiquetas claras y asociadas correctamente al campo correspondiente.

No se utilizarán únicamente placeholders como sustitutos de las etiquetas.

### 10.4 Navegación por teclado

La navegación principal, formularios, botones, enlaces y elementos interactivos deberán poder utilizarse mediante teclado.

El orden de navegación deberá ser lógico y coherente con la estructura visual de la página.

### 10.5 Tamaños táctiles

Los elementos interactivos deberán disponer de un tamaño y separación adecuados para facilitar su utilización mediante pantallas táctiles.

Especialmente:

- botones;
- enlaces;
- campos de formulario;
- elementos desplegables;
- controles de navegación.

La accesibilidad deberá mantenerse tanto en escritorio como en dispositivos móviles.

## 11. Estados, interacciones y animaciones

Los elementos interactivos deberán proporcionar una respuesta visual clara cuando el usuario interactúe con ellos.

Las interacciones deberán ser sencillas, rápidas y discretas, evitando efectos innecesarios.

### 11.1 Estado normal

Todos los elementos deberán presentar un estado inicial claro y fácilmente reconocible.

Los elementos interactivos deberán diferenciarse visualmente de los elementos que únicamente muestran información.

### 11.2 Hover

En dispositivos que dispongan de puntero, los elementos interactivos podrán modificar ligeramente su apariencia al pasar el cursor sobre ellos.

Se podrán utilizar cambios sutiles de:

- fondo;
- borde;
- sombra;
- color;
- posición.

Los efectos deberán ser discretos y no provocar movimientos bruscos del contenido.

### 11.3 Focus

Los elementos interactivos deberán mostrar un estado de focus claramente visible al utilizar el teclado.

El estado de focus deberá mantener suficiente contraste y no depender únicamente del color.

### 11.4 Error

Cuando se produzca un error de validación:

- el usuario deberá identificar claramente que existe un problema;
- el mensaje deberá explicar qué debe corregirse;
- el elemento afectado podrá resaltarse visualmente;
- el contenido no deberá desplazarse de forma inesperada.

### 11.5 Resultado

Cuando una calculadora genere un resultado:

- el resultado deberá aparecer claramente diferenciado;
- deberá ser fácil de localizar;
- la información principal tendrá mayor protagonismo visual que la información secundaria.

No se utilizarán animaciones llamativas para mostrar los resultados.

### 11.6 Estado vacío

Antes de realizar un cálculo, la zona de resultados podrá permanecer oculta o mostrar un estado inicial sencillo.

No deberá mostrarse información que pueda confundirse con un resultado calculado.

### 11.7 Animaciones y transiciones

Las animaciones deberán utilizarse únicamente cuando mejoren la comprensión o la sensación de interacción.

Se priorizarán transiciones:

- cortas;
- suaves;
- discretas.

No se utilizarán animaciones que dificulten la lectura, retrasen el uso de la calculadora o generen distracciones.

La web deberá respetar la preferencia `prefers-reduced-motion` del usuario.

### 11.8 Elementos desplegables

Los elementos desplegables deberán resultar claramente interactivos.

El usuario deberá poder identificar visualmente que el encabezado puede abrirse o cerrarse.

Se utilizarán como mínimo:

- un encabezado claramente identificable;
- un indicador visual de apertura y cierre, como una flecha o chevron;
- una zona de interacción suficientemente amplia.

Al interactuar:

- el estado abierto y cerrado deberá diferenciarse claramente;
- el indicador visual deberá reflejar el estado actual;
- la apertura y el cierre podrán utilizar una transición suave;
- el contenido no deberá producir movimientos bruscos o inesperados.

Los elementos desplegables deberán poder utilizarse mediante teclado y deberán mantener un comportamiento adecuado en dispositivos móviles.

Se deberá respetar `prefers-reduced-motion` cuando se utilicen transiciones.

## 12. Espaciado y dimensiones

El sistema de espaciado y dimensiones deberá mantener una apariencia ordenada, equilibrada y consistente en todas las páginas.

Los valores utilizados deberán seguir criterios comunes y evitar ajustes independientes para cada componente.

### 12.1 Anchos

El contenido principal deberá utilizar un ancho máximo que facilite la lectura y evite que los elementos se extiendan excesivamente en pantallas grandes.

Los formularios y calculadoras deberán mantener un ancho cómodo para su utilización.

En dispositivos móviles se aprovechará el ancho disponible respetando márgenes laterales adecuados.

### 12.2 Márgenes

Los márgenes deberán utilizarse para separar claramente:

- secciones;
- títulos;
- párrafos;
- tarjetas;
- formularios;
- resultados.

Se mantendrá una escala de espaciado coherente en toda la web.

### 12.3 Padding

Los componentes deberán disponer de espacio interior suficiente para evitar una apariencia comprimida.

Se aplicará especialmente a:

- tarjetas;
- botones;
- campos;
- bloques de información;
- resultados.

### 12.4 Alturas

Los campos y botones deberán tener una altura adecuada para facilitar tanto la lectura como la interacción táctil.

Las alturas no deberán ser excesivas ni generar una interfaz innecesariamente grande.

### 12.5 Bordes

Los bordes se utilizarán principalmente para:

- delimitar componentes;
- separar visualmente contenidos;
- indicar estados;
- mejorar la identificación de campos.

Deberán ser discretos y coherentes entre componentes equivalentes.

### 12.6 Radios

Las esquinas redondeadas deberán utilizarse de forma consistente en componentes que las incorporen.

El radio será moderado y deberá mantener una apariencia profesional, evitando tanto esquinas completamente rectas como formas excesivamente redondeadas.

Los valores concretos de espaciado, dimensiones y radios deberán centralizarse siempre que sea posible para facilitar futuros ajustes del diseño.

## 13. Iconos e imágenes

Los iconos e imágenes deberán utilizarse únicamente cuando aporten valor a la comprensión, navegación o identificación de los contenidos.

La web deberá mantener una apariencia limpia y rápida, evitando recursos visuales innecesarios.

### 13.1 Iconos

Los iconos podrán utilizarse para:

- reforzar acciones;
- facilitar la comprensión de determinados elementos;
- acompañar elementos de navegación.

Deberán mantener un estilo visual coherente en toda la web.

Los iconos no deberán sustituir textos importantes cuando puedan dificultar la comprensión.

### 13.2 Imágenes

Las imágenes se utilizarán únicamente cuando aporten información o valor visual real.

No se añadirán imágenes decorativas únicamente para ocupar espacio.

Cuando se utilicen imágenes deberán:

- estar relacionadas con el contenido;
- tener un tamaño adecuado;
- optimizarse para no perjudicar el rendimiento;
- disponer de texto alternativo cuando corresponda.

Las calculadoras no necesitan utilizar imágenes decorativas para funcionar correctamente.

Se priorizará una interfaz basada en:

- tipografía;
- espacios;
- tarjetas;
- iconos sencillos;
- colores;
- componentes de interfaz.

### 13.4 Consistencia visual

No se mezclarán diferentes estilos de iconos o imágenes sin una razón concreta.

Los recursos visuales deberán integrarse con la identidad visual definida en el resto del sitio.

### 13.5 Rendimiento

Los recursos gráficos deberán mantenerse al mínimo necesario.

No se incorporarán librerías de iconos, fuentes externas o imágenes pesadas cuando exista una alternativa sencilla que permita conseguir el mismo resultado.

## 14. SEO visual y estructura de contenido

El diseño visual deberá favorecer la comprensión del contenido y mantener la estructura SEO existente.

El diseño no deberá utilizar elementos visuales para sustituir contenido textual relevante.

### 14.1 Jerarquía de contenido

Cada página deberá mantener una jerarquía clara mediante:

- un H1 principal;
- H2 para las secciones principales;
- H3 cuando sea necesario;
- párrafos y listas correctamente estructurados.

La estructura de títulos deberá responder a la organización real del contenido.

### 14.2 Contenido visible

El contenido importante para el usuario deberá estar disponible en el HTML y ser fácilmente accesible.

No se ocultará contenido relevante exclusivamente para conseguir una apariencia más limpia.

Los elementos desplegables podrán utilizarse para contenido secundario, manteniendo siempre una estructura accesible.

### 14.3 Enlaces internos

El diseño deberá facilitar la navegación entre páginas relacionadas.

Los enlaces internos deberán:

- utilizar textos descriptivos;
- aparecer en contextos relevantes;
- facilitar el acceso a calculadoras y guías relacionadas;
- mantener una estructura natural.

No se añadirán enlaces únicamente para aumentar artificialmente la cantidad de enlaces internos.

### 14.4 URLs y estructura existente

El rediseño visual no deberá modificar las URLs actuales ni la estructura SEO ya establecida.

Se deberán conservar:

- URLs;
- canonical;
- sitemap;
- robots.txt;
- títulos SEO;
- meta descriptions;
- estructura de navegación existente.

### 14.5 Experiencia de usuario

La estructura visual deberá facilitar que el usuario encuentre rápidamente la información que busca.

Una buena experiencia de usuario tendrá prioridad frente a la introducción de elementos diseñados exclusivamente para SEO.

### 14.6 Evitar sobreoptimización

No se deberán introducir:

- textos repetitivos;
- palabras clave innecesarias;
- bloques de enlaces artificiales;
- contenido oculto con finalidad SEO;
- elementos visuales que perjudiquen la experiencia del usuario.

El SEO deberá integrarse de forma natural dentro de la estructura y el contenido de la web.

## 15. Rendimiento

El rediseño visual deberá mantener un buen rendimiento y no introducir elementos que ralenticen innecesariamente la web.

La velocidad de carga y la respuesta de las calculadoras tendrán prioridad frente a efectos visuales secundarios.

- utilizar estilos excesivamente complejos;

### 15.4 Imágenes y recursos

No se incorporarán recursos pesados como parte de la decoración.

### 15.5 Animaciones

No deberán afectar negativamente a la carga, interacción o fluidez de la página.

### 15.6 Carga de la página

La página deberá mostrar rápidamente el contenido principal y permitir utilizar las calculadoras sin esperas innecesarias.

El diseño deberá evitar elementos que bloqueen la carga del contenido o de las herramientas.

### 15.7 Rendimiento en móvil

El rendimiento deberá comprobarse también en dispositivos móviles, donde las conexiones y recursos disponibles pueden ser más limitados.

El rediseño no deberá sacrificar velocidad por conseguir efectos visuales adicionales.
